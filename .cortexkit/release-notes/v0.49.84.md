# v0.49.84

This patch fixes two faults on OpenCode 2: the saved model list lost image support and limits after the first reply, so the memory mural never rendered, and an undo left records behind for the messages it removed.

## Upgrading

Update the plugin with `npx @cortexkit/magic-context@latest doctor`, then restart your host. No database migration is needed.

## Fixed

- **OpenCode 2: every model was saved as not accepting images, so the memory mural never rendered** (issue 993, thanks @mgt-l). Magic Context keeps a list of each model's limits and whether it accepts images. At start it fills that list from the host's full model catalog. After the first reply of a session it refreshed the list, kept only the limits of each model, and replaced the whole list with the result. Every model then read as text-only, and the mural was skipped without a log line. Models that the refresh did not list were removed with their limits, and a session on such a model used a detected limit or a 200,000-token default until a later refresh. The fault was in every release since 0.43.0. Now the refresh adds to the list: a model or a value that the refresh does not carry stays as it was, limits that it carries win, and image support changes only when the host states the model's capabilities. A model defined in a project, which the plugin first sees at the first reply, gets its image support there. A list that is already damaged repairs itself at the next start or the next first reply; you do not need to delete a file. OpenCode 1 and Pi did not have the fault.
- **OpenCode 2: an undo left records for the removed messages** (issue 988, thanks @null-axiom). When you undo messages in OpenCode 2 and then continue, the host deletes those messages. Magic Context kept their tags, its per-message records and its saved copy of the last request. The stale tags were counted in status, and the next request could log a false warning that the request had changed. Now, when the undo is committed, Magic Context removes its records for exactly the messages the host deleted. It deletes only for messages it saw before the undo and no longer finds after it. If it cannot prove which messages were removed, for example after a restart between the undo and the commit, it leaves the records in place and logs why. A session without an undo sends the same bytes as before.
- **OpenCode 2: summary rebuild data could outlive the summaries it belonged to** (issue 988). When an undo retires summaries, data staged for a summary rebuild is discarded with them.

## Changed

- When the mural is on and the session's model does not accept images, the log now says so once per session and model: `[mural] skipped: model <provider/model> does not accept images`.
