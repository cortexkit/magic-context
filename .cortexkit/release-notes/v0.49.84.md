# v0.49.84

This patch fixes three faults on OpenCode 2: the saved model list lost image support and limits after the first reply, so the memory mural never rendered; an undo left records behind for the messages it removed; and a storage notice could reach the model or end a turn early.

## Upgrading

Update the plugin with `npx @cortexkit/magic-context@latest doctor`, then restart your host. No database migration is needed.

**If you use the memory mural (`mural.enabled`) on OpenCode 2 with a text-only model that you defined yourself:** the mural now works on OpenCode 2, and Magic Context takes the host's word for which models accept images. OpenCode 2 lists a model that you define without `capabilities` as accepting text and images. For a text-only model, set `capabilities.input` to `["text"]` on that model in your OpenCode config. Otherwise the mural image is sent to it, and a server that refuses images will refuse the request.

## Fixed

- **OpenCode 2: every model was saved as not accepting images, so the memory mural never rendered** (issue 993, thanks @mgt-l). Magic Context keeps a list of each model's limits and whether it accepts images. At start it fills that list from the host's full model catalog. After the first reply of a session it refreshed the list, kept only the limits of each model, and replaced the whole list with the result. Every model then read as text-only, and the mural was skipped without a log line. Models that the refresh did not list were removed with their limits, and a session on such a model used a detected limit or a 200,000-token default until a later refresh. The fault was in every release since 0.43.0. Now the refresh adds to the list: a model that the refresh does not list stays as it was, a listed model takes the host's current limits, and image support changes only when the host states which inputs the model accepts. A model defined in a project, which the plugin first sees at the first reply, gets its image support there. A list that is already damaged repairs itself at the next start or the next first reply; you do not need to delete a file. OpenCode 1 and Pi did not have the fault.
- **OpenCode 2: an undo left records for the removed messages** (issue 988, thanks @null-axiom). When you undo messages in OpenCode 2 and then continue, the host deletes those messages. Magic Context kept their tags, its per-message records and its saved copy of the last request. The stale tags were counted in status, and the next request could log a false warning that the request had changed. Now, when the undo is committed, Magic Context removes its records for exactly the messages the host deleted. It deletes only for messages it saw before the undo and no longer finds after it. If it cannot prove which messages were removed, for example after a restart between the undo and the commit, it leaves the records in place and logs why. A session without an undo sends the same bytes as before.
- **OpenCode 2: summary rebuild data could outlive the summaries it belonged to** (issue 988). When an undo retires summaries, data staged for a summary rebuild is discarded with them.
- **OpenCode 2: a storage notice could reach the model or end a turn early.** When Magic Context cannot use its own store, it puts a notice for you into the conversation. The model must never read it, and the notice must not start a reply. Three faults were found on all four supported OpenCode 2 versions. A side question asked after a notice carried the notice text to the model. A notice that arrived while a tool was running ended the turn before the model saw the tool's result. A fork sent copies of earlier notices to the model. Now side questions and forks leave the notices out, and a turn that has a tool result or a new prompt continues. A notice that arrives in an idle session still starts no reply. A fork that has been sending copied notices rewrites its prompt cache once after the update, from the first copied notice on.

## Changed

- When the mural is on and the session's model does not accept images, the log now says so once per session and model: `[mural] skipped: model <provider/model> does not accept images`.
