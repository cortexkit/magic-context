# v0.49.79

This patch fixes the weekly memory tidy-up reporting a failure when it had nothing safe to change, and keeps a safety net for OpenCode 2 sessions that hold an image.

## Upgrading

Update the plugin with `npx @cortexkit/magic-context@latest doctor`, then restart your host. No database migration is needed.

## Fixed

- **A tidy-up run whose every proposed change was refused is no longer a failure** (issue 978). The `curate` task lets a model propose updates and archives, and safety checks refuse a change that would lose content or archive a memory with no live successor. When every proposal was refused, the run ended as `MC-D06 · Curate returned no completed ctx_memory tool result`, was counted as a model failure, and was retried on the fallback model for the same result. Such a run now completes and says what happened, for example `curate: no changes; 4 operations refused (content-loss ×2, missing-active-same-category-successor ×2)`. No fallback model is tried. A run that applied some changes and had others refused reports both. A run that only read memories and decided to change nothing also completes.
- **The tidy-up no longer stays on one category.** The task works through one memory category per run. It moved to the next category only after a completed run, so a category that failed the same way every time kept its turn and the others never ran. It now also moves on after a failure that a retry cannot fix. A provider error or timeout still retries the same category.
- **Pi and Oh My Pi: a refused tidy-up change was reported as applied.** The run detail said `1 memory operation applied` when the safety checks had refused the change and no memory was touched. Pi now reports refusals the way OpenCode does.
- **OpenCode 2: a session with an image keeps its fallback when the store is briefly busy.** When Magic Context's store is locked for a moment, the plugin resends the last good request instead of refusing the turn. A saved request that held an image could never be resent, because its size could not be measured, so such a session had its turn refused. The saved image is now measured like the live one, and the resent request is byte-identical to the original.
