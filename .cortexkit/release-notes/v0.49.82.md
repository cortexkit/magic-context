# v0.49.82

This patch fixes forked sessions on OpenCode 2, stops background runs from showing as finished sessions there, and tells you when memories stay behind after a project folder changes.

## Upgrading

Update the plugin with `npx @cortexkit/magic-context@latest doctor`, then restart your host. No database migration is needed.

## Fixed

- **OpenCode 2: a forked session lost the summarized part of its history** (issue 968, thanks @JohanTG). A fork got its parent's messages under new ids, so the parent's summaries no longer matched and were dropped, and the messages they covered were cut as well. The fork then started without that history and its summarizer could not continue. A new fork now keeps every parent summary that Magic Context can prove still describes the same messages, in order, and sends the rest of the history raw. The parent session is never changed. A fork made by an earlier version is not repaired by itself: `/ctx-status` and the sidebar now say "This fork's saved history has a gap", and `/ctx-recomp` rebuilds it. On OpenCode Web and Desktop this line appears only once command output is visible there, which is a separate fix.
- **OpenCode 2: background runs appeared as finished sessions** (issue 947, thanks @iceteaSA). Summaries and maintenance run in hidden sessions. OpenCode 2 announced each one as "Session done" and listed it. These runs now start under one holder session per project folder, which OpenCode treats as their parent, so they are quiet. The holder is permanent and can't be used for chat. OpenCode 2.3.0 reports every child session's completion to its parent, so on that one version the runs stay as they were; 2.3.1 and later are quiet.
- **Memories could stay behind unnoticed when a session's project changed** (issue 946, thanks @tamasys). When a plain folder gets its first Git commit, or a session moves to another folder (`/cd`), the project's identity changes and its memories stay under the old one. Magic Context now says so once: as a notice in the terminal, in `/ctx-status` and the sidebar on OpenCode 2, and in `doctor`. The message shows how many memories stayed and a `doctor merge-identities` command that previews the move; add `--apply` to move them. Nothing moves by itself.
- **`ctx_memory`: the tool description did not say which arguments every action needs** (issue 943, thanks @morpheus9393 for the report and @endynamoo for the pull request). Hosts that validate tool calls strictly refused calls that left out the unused arguments, and the model could not tell from the description. Each action's description now states the arguments to send and what to put in the unused ones, on OpenCode 1, OpenCode 2, Pi and Oh My Pi.

## Known limits

- A fork whose unsummarized history is larger than the model's window can have its first turn refused by the provider. The next turn waits for the summarizer and then fits.
- A fork of a fork that was already damaged by an earlier version inherits that damage. Run `/ctx-recomp` in it.
