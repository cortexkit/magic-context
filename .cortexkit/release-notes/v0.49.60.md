# v0.49.60

This patch fixes Pi sessions that could stop shrinking after Pi's own compaction or a failed reply, makes Magic Context take over when Pi reports a context overflow, counts images at their token cost instead of their size in bytes, and fixes Oh My Pi's `antigravity-cli` provider re-compacting after every compaction.

## Upgrading

Update the plugin and restart the host. No database migration is needed.

A Pi or Oh My Pi session whose newest history summary ends partway through a turn rebuilds its request once after the update. That turn's prompt comes back, so the model sees the prompt it is answering. Sessions whose summary ends at the end of a turn send exactly the same requests as before.

## Fixed

- **Pi: a session stopped shrinking and kept sending its summarized history (issue 938, thanks @expiren for the detailed report and the session details):** Magic Context removes the messages a history summary covers by finding the summary's last message in the request. When Pi hides that message (a failed reply it retries), Magic Context places the cut by position in the session instead. That fallback gave up whenever the request also held Pi's own compaction summary, so every summarized message, images included, stayed in the request on every turn. The fallback now cuts exactly as the normal path does, and logs when a cut cannot be placed instead of silently cutting nothing. It never removes the prompt of the turn the summary ends in, so the model never answers a prompt it can't see.
- **Pi: a request could go out without the history summary:** if inserting the summary failed, the turn went out with neither the summary nor the cut. Magic Context now replays the last good request, or refuses the turn when there is none.
- **Pi: overflows that Pi detected left Magic Context's recovery off (issue 938):** Pi recognises some provider errors as context overflows that Magic Context's own patterns missed. Magic Context now also asks the running host's overflow check, and it arms its overflow recovery when Pi is about to retry a request that failed for an overflow. A reply that succeeded but reported more input than Pi's configured window arms nothing, because the provider accepted it.
- **Pi: images counted at their size in bytes (issue 938):** a base64 image counted as tens of thousands of tokens in Magic Context's size checks, and images in tool outputs counted as fixed, so the emergency drop could not remove them. Images now count at a fixed token cost per image, can be dropped with the tool output that carries them, and no longer block replaying the last good request.
- **Oh My Pi, `antigravity-cli`: compacting again right after a compaction (issue 939, thanks @DeemoASCII):** this provider reports each tool-call step with only `usage.contextTokens`. Magic Context ignored that field, so after a compaction it kept reading the old peak and compacted again. It now uses `contextTokens` when the other usage counters are all zero; other providers are unchanged. `antigravity-cli` also gets the same window as `google-antigravity`, whose output is not reserved out of the input window.
