# v0.49.47

This patch keeps Claude's kept reasoning valid when a session's tool list changes, makes a manual `/compact` on OpenCode 2 land queued cleanup in the rebuild it already causes, and reads assistant replies that OpenCode 2.2.6 stores in its new parts table.

## Upgrading

- Restart OpenCode or Pi after updating. No database migration is needed.
- OpenCode 2.2.6 sessions that already store assistant replies in the parts table rebuild their history once after this update. Other sessions are unaffected.

## Fixed

- **Kept reasoning survives a tool list change:** on Claude Fable 5.1 and 5.2, Mythos, and the 5.5 models, a thinking block stays valid only while everything sent before it is unchanged, including the list of tools. When a tool was added, removed or edited mid-session (an MCP server connecting, for example), the next request still carried thinking bound to the old list, and Fable 5.2 and Mythos rejected it with a 400 error. On OpenCode 2 and Pi, Magic Context now notices the change and removes the affected thinking on that turn, together with any cleanup it was waiting to do, since that turn rewrites the prompt anyway. OpenCode 2 also recovers on the next turn after such a rejection, which it didn't before. OpenCode 1 can't see each request's tools, so it keeps recovering after one rejected request.
- **A manual `/compact` on OpenCode 2 carries the queued cleanup:** a manual compaction rebuilds the start of the prompt, so the provider's cache is lost on the next request anyway. Magic Context now removes the content the agent already marked as no longer needed, and does its routine cleanup, on that request instead of waiting for a second rebuild. If the turn was holding recent reasoning, that reasoning is removed with the old history rather than sent behind the new one, which the provider would reject. This also works when the session was reopened just before `/compact`.
- **OpenCode 2.2.6 replies stored in the parts table are read:** OpenCode 2.2.6 can store assistant replies in a separate parts table, with `experimental.part_rows`, and for some replies it inserts complete. Magic Context didn't read that table. So once OpenCode 2 compacted the session (a manual `/compact`, or the checkpoint Magic Context adds to keep long sessions fast), every earlier assistant reply was missing from the request, and summaries saw no assistant text. It now reads the table exactly as OpenCode does.
