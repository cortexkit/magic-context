# v0.49.81

This patch fixes an unaccounted prompt-cache rewrite on OpenCode 2 and makes `/compact` shrink the next request on OpenCode 2.3.1 and later.

## Upgrading

Update the plugin with `npx @cortexkit/magic-context@latest doctor`, then restart your host. No database migration is needed. If you run OpenCode 2.3.1 or later, also run `npx @cortexkit/magic-context@latest doctor --fix` once; see the first item below.

## Fixed

- **OpenCode 2.3.1 and later: `/compact` did not shrink the next request.** These versions prepare a compaction in the background after a high-usage reply, and `/compact` can then use the prepared answer without calling Magic Context again. Your history stayed intact and nothing was sent twice, but the request after `/compact` was as large as before; a second `/compact` worked. Setup now writes `"compaction": { "background": false }` to the OpenCode config when Magic Context manages compaction, and `doctor` reports the setting when it is on. `doctor --fix` turns it off in your user config, and in a project config only when that file turns it on. OpenCode reads this setting without a restart, and older OpenCode 2 versions ignore it.
- **OpenCode 2: a compaction the host asked for early could cost a full prompt-cache rewrite.** When OpenCode asked Magic Context for a compaction summary before it had recorded the checkpoint (background preparation on 2.3.1 and later, automatic checkpoints on every version, provider compaction mode on older ones), Magic Context stored a newly rendered history baseline. If a new summary was waiting at that moment, the next request sent the new baseline and the provider read the whole prompt again, on a turn that logged no change. Such a request now renders its answer without storing anything, so the next request is byte-identical to the one before. The stored baseline changes only on a real rebuild.
- **OpenCode 2: an early compaction request could make a subagent keep tools it should not have.** The same request could use up the attempts to find out whether a session is a subagent, before the session's first managed request. It no longer touches that.
- **Dashboard: an archived OpenCode session could rename or hide a live project's card** (issue 960). The card took its name and path from any session of the project, including archived ones, and a card could disappear when the archived session's folder no longer existed. Cards now use live sessions only. This ships with the next Dashboard release.

## Changed

- The log line for a compaction request now says whether the host had recorded a checkpoint (`row=running`) or asked early (`row=none`).
- `ARCHITECTURE.md` no longer uses our internal name "mode 3". It says "runner-hosted session".
