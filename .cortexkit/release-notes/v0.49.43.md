# v0.49.43

This patch makes a refused turn on Pi and Oh My Pi actually stop before it reaches the provider, and lets Oh My Pi's Cursor provider work with Magic Context.

## Upgrading

- Restart Pi or Oh My Pi after updating. No database migration is needed.

## Fixed

- **A refused turn on Pi or Oh My Pi could still reach the model:** when Magic Context refused to send a turn (for example "Magic Context could not safely prepare this turn"), Pi and Oh My Pi still sent the original request. The model answered, its tool calls ran, and the reply was then discarded as aborted. A refused turn is now stopped before anything is sent, no tools run, and the refusal message is shown. The next turn works normally.
- **Every Cursor turn on Oh My Pi was refused:** Magic Context couldn't read the request format of Oh My Pi's Cursor provider (`cursor-agent`), so it refused every turn. It now understands that format, including Cursor's content-addressed history, and checks Cursor turns the same way as other providers. This is checked against Oh My Pi 18.13.2, 18.18.0 and 18.18.1. When a request format isn't recognized, the refusal now names the provider and format, so it's easy to report. Thanks to @Zireael for the detailed report (#880).
