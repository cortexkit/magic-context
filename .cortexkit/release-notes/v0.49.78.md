# v0.49.78

This patch fixes OpenCode 2 sessions that fail on every prompt after an image attachment is restored.

## Upgrading

Update the plugin with `npx @cortexkit/magic-context@latest doctor`, then restart OpenCode. No database migration is needed. A session that was already failing works again on its next prompt, with no manual repair. Pi, Oh My Pi and OpenCode 1 users are not affected and can update whenever they like.

## Fixed

- **OpenCode 2: a restored image could make every turn of a session fail** (issue 977). After a host compaction, Magic Context rebuilds older messages from the store. An image attachment in such a message could be handed to OpenCode in an outdated shape, and OpenCode 2.3 then failed the request before it reached any model, on every later prompt, with `undefined is not an object (evaluating 'e.source.data.length')`. It happened when the first draft a freshly started plugin saw began with a system message, which OpenCode 2.3 writes for a reasoning-effort or model change: the plugin then decided, for as long as OpenCode kept running, that the host did not need the newer attachment shape. The decision no longer depends on which message comes first, and the outdated shape is removed, since no supported OpenCode 2 version accepts it.
- **OpenCode 2: an attachment the host cannot use no longer stops the request.** The last step before a request is handed back to OpenCode now checks every image part. One the host could not use is rebuilt in the form the host needs, so the image still reaches the model. When that is not possible, and when a restored attachment cannot be rebuilt at all, a short text note takes its place, so the rest of the message still reaches the model.
