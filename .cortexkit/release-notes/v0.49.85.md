# v0.49.85

This patch fixes a crash at exit on Pi that could happen while a local embedding was being computed.

## Upgrading

Update the plugin with `npx @cortexkit/magic-context@latest doctor`, then restart your host. No database migration is needed.

## Fixed

- **Pi: the process could abort at exit while a local embedding was running** (issue 995, thanks @chpock). With the local embedding provider, Magic Context computes embeddings in a worker that calls a native library. When Pi shut down, Magic Context stopped that worker at once, also in the middle of a native call, and Pi's shutdown did not wait for it. Under Node the process then ended with `terminate called after throwing an instance of 'Napi::Error'` and exit code 134 in place of a normal exit. In our reproduction on Node 26 this happened in 18 of 20 exits that had an embedding in flight. Now stopping the worker is a request. The worker finishes the call it is running, starts no further one, releases the model and ends by itself, and Pi's shutdown waits for that. The wait was 10 to 310 ms in the test runs. The same holds for a worker that a configuration or model change retired shortly before the exit.
- **Oh My Pi:** the same abort happened on Bun in a few of 20 such exits. It is fixed by the same change.
- **A worker that does not stop is bounded.** If a worker does not end within 5 seconds, it is terminated as before, and a stop always settles within about 7 seconds. One log line says that the worker was terminated and whether an embedding was running.

OpenCode itself was not at risk: there the worker runs in a child process. That child is now asked to stop in the same way and is no longer killed in the middle of a call.

## Known limit

An exit that does not go through the host's own shutdown, such as a fatal error or another extension that calls `process.exit`, can still abort under Node when an embedding is running at that moment. Ctrl+C, Ctrl+D, `/quit`, SIGTERM and SIGHUP in Pi's interactive mode go through the shutdown and are covered.

## Changed

- When a running embedding worker is stopped, the log has one line with the process id, whether an embedding was running, and how long the stop took: `[magic-context] embedding worker stopped (…)`.
- Embedding results and the speed of a normal embedding request are unchanged.
