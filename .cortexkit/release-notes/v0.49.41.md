# v0.49.41

This patch removes multi-second pauses on long OpenCode 1 sessions when Magic Context moves OpenCode's compaction marker.

## Upgrading

- Restart OpenCode after updating. No database migration is needed.

## Fixed

- **Long OpenCode 1 sessions paused for seconds when history was folded:** since 0.49.36, moving OpenCode's compaction marker first checked the whole session for a row that still pointed at the old marker, and it did that while holding OpenCode's database write lock. On a long session that check took 10 to 30 seconds. The turn waited that long, and so did every other session on the same OpenCode server that tried to write. The check now runs before the lock, on a separate read-only connection, and on later moves it reads only compaction rows and rows written since the previous move. Under the lock, Magic Context rereads just those rows to confirm nothing changed. The protection added in 0.49.36 is unchanged: a marker that OpenCode's own compaction still points at is never deleted.
