# v0.49.72

This patch stops a search from sending a project's whole memory store to the embedding provider at once, and stops effort changes from rewriting the prompt cache on newer Claude models.

## Upgrading

Update the plugin and restart OpenCode, Pi or Oh My Pi. No database migration is needed.

## Fixed

- **Search sent every memory to the embedding provider at once (#957, thanks @iceteaSA):** after stored memory vectors were lost, for example after changing the embedding model, a search with no keyword match embedded every memory that had no vector in a single request. On a large project that request timed out or tripped the provider's failure guard. A search now embeds at most 50 such memories, in requests of at most 10, chosen in a fixed order. The rest are still found by keyword, and the background job fills in their vectors as before.
- **Effort changes rewrote the prompt cache on newer Claude models:** changing the reasoning effort mid-session made Magic Context rebuild the request on Sonnet 5.5, Haiku 5.5, Fable 5.2, Mythos 5.1 and Mythos 5.2, and on Opus 5.5 when reached through Amazon Bedrock or Google Vertex. These models carry the effort change without touching the cached prompt, so the rebuild was the only cost. They now keep their cache, as Opus 5.5 and Fable 5.1 already did. Older models are unchanged.
