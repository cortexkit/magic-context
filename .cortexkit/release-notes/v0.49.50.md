# v0.49.50

This patch adds an output-width option for embedding models that support it, stops background runs from retrying a model whose provider said when to come back, and fixes a wrong context-size reading after an Anthropic server-side fallback on OpenCode 2.

## Upgrading

Restart your host after updating. No database migration is needed.

## Added

- **`embedding.dimensions` (issue 405):** an optional output width for OpenAI-compatible embedding models that can return shorter vectors, such as OpenAI's `text-embedding-3-*` and Qwen3-Embedding. Set it to an integer from 1 to 8192 in your user config, and Magic Context sends it as the `dimensions` field of each embedding request. Leave it unset and nothing changes: the request omits the field, and your stored vectors stay valid. Setting or changing it re-embeds your memories and history at the new width, because vectors of different widths can't be compared. Magic Context refuses a response whose width differs from the one you asked for. A project config can't set this option; it is read from your user config only. Thanks to @yiyi-wei for the contribution.

## Fixed

- **Background runs no longer retry a model that is out of quota:** when the summarizer or the dreamer has `fallback_models` and a provider refuses the first model with a time to retry after (a used-up quota window, for example), every later run used to try that model again first, fail, and fall back. Each run left one failed child session and, on OpenCode, an error box in the parent session's terminal. Later background runs now skip that model until the time the provider gave and start on the next one in your list. Your configured order returns after that time, and a successful run on the model clears it at once. When every model in the list is waiting, Magic Context still tries the one that frees soonest. A restart clears this memory, and your own session's requests are never rerouted. It works on OpenCode 1 and on OpenCode 2.2 or newer. Pi and older OpenCode 2 versions don't pass the provider's retry time to plugins, so runs there fall back as before.
- **Context size after an Anthropic server-side fallback on OpenCode 2 (issue 877):** when Anthropic refuses a request on one model and answers it on its fallback model, the reported usage is the sum of both attempts. Magic Context read that sum as the size of the prompt, so one fallback step could look like 110% of the window. The session then held turns, refused them, or summarized early. With the CortexKit anthropic-auth plugin, which records each attempt's usage, Magic Context now takes the size of the attempt that produced the reply. When that record is missing or unreadable, it keeps the previous reading instead of the summed one. Thanks to @iceteaSA for the report and the fix.
