# v0.49.57

This patch stops Oh My Pi subagents from being cut off on their first turns, says clearly why a turn was refused when history summaries keep failing, clears stale context limits after a model or route change, and stops the memory mural from showing boxes for memories in non-Latin scripts.

## Upgrading

Update the plugin and restart the host. OpenCode 2 does not update npm plugins by itself, so update it as the docs describe. No database migration is needed.

## Fixed

- **Oh My Pi: task subagents refused and ended within seconds (issue 931, thanks @DeemoASCII for the report and the root-cause work):** Magic Context checks that the request Oh My Pi sends matches the turn it prepared. On Oh My Pi 18.19 and 18.20, three request shapes failed that check, and the refusal ended the subagent:
  - **Parallel tool calls stored in a different order.** When a reply's parallel tool calls finished out of order, Oh My Pi replayed them in their finishing order, not their order in the message. This is what ended the reporter's subagents.
  - **Repeated tool-call ids.** Some providers reuse a tool-call id, in one reply or across replies. Oh My Pi renames the repeat, but its replay still sends the original ids, adds the renamed call, and gives an unanswered call a placeholder result. Both full requests and chained continuations are covered.
  - **The `# Juice` reasoning item.** When Oh My Pi turns reasoning off for some OpenAI models, it adds a short instruction item at the end of the request. It is now recognized exactly.
  
  Any other difference is still refused. Oh My Pi's automatic Auto-learn capture turns stay off under Magic Context, because they resend the raw, unmanaged conversation. They are now refused quietly, without refusal entries in your session.
- **A refused turn blamed the wrong summary failure (issue 930, thanks @mcheiyue):** when context reaches 95% and a history summary does not finish in time, the turn is refused, as before. The message used to quote whatever summary error was stored last, often from an earlier run. It now names the summary run it waited for and its state, how many summary runs have failed in a row and since when, how full the context is, and what to do: check `/ctx-status`, change the history model or its fallbacks, or run `/ctx-recomp`. Errors are shown with paths and secret-shaped values removed. After 3 failed summary runs in a row, a notice now tells you so before the session reaches 95%. It repeats only if the failures continue. This works the same on OpenCode and Pi.
- **A stale context limit stayed after a model or route change (issues 928 and 929, thanks @mcheiyue):** when a provider refuses a request for its length, Magic Context records that model's limit. On OpenCode 2 and Pi, a later, larger request that the provider accepted did not clear the limit. On OpenCode, switching away from a model whose last request was refused did not clear it either, so it came back when you switched back. Now an accepted request above the limit clears it on every host, and leaving the model that owns a limit clears it. On Pi, the turn that switches models no longer applies the previous model's limit. A limit is never cleared by a request that fits under it, because that proves nothing. If a gateway serves one model name through routes with different limits, switching to another model for one turn and back clears a stale limit.
- **The memory mural drew boxes for memories in non-Latin scripts (issue 932, thanks @G0-0000):** the mural's font has no glyphs for Chinese and many other scripts, so those memories drew as rows of identical boxes, and the image was still sent and counted. The mural now leaves out any memory it cannot draw, and sends no image when it can draw none. Accented letters and typographic quotes and dashes are drawn as their plain forms. Murals that drew correctly before are unchanged.
