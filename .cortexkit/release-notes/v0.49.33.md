# v0.49.33

This patch stops OpenCode 2 sessions from paying two full prompt-cache writes when their tool list changes.

## Upgrading

- Restart OpenCode after updating. No database migration is needed.

## Fixed

- **A tool-list change cost two full cache writes on OpenCode 2 (#819, thanks @iceteaSA):** when a plugin reload added, removed or renamed tools, the provider lost its cached prompt on the next request, but Magic Context treated that pass as a cache hit. Its history head stayed as it was and its queued drops stayed held, so each session paid a second full write later, when those drops finally landed. On OpenCode 2, a change to the names or descriptions of the tools a session sends now rebuilds the history head once, and the queued drops and cleanup land in that same rebuild.
  - **Upgrading:** the first pass after the upgrade records each session's tool list without rebuilding.
  - **Schema-only differences:** a change to a tool's schema alone never counts, so it can't cause a rebuild that the provider wouldn't already pay for.
  - **Known limits:** a plugin that changes the tool list after Magic Context's hook isn't seen. A tool entry that OpenCode drops before sending can still cause one rebuild when its description changes.
  - **OpenCode 1 and Pi:** unchanged. Their tool-list signal is shared by every session in the process, so it still isn't used.
