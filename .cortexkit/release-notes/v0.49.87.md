# v0.49.87

This patch fixes seven faults on OpenCode 2, OpenCode 1 and Pi, and makes automatic search answer in time after a pause. Most of the faults were found by running end-to-end tests that no CI job had run before.

## Upgrading

Update the plugin with `npx @cortexkit/magic-context@latest doctor`, then restart your host. No database migration is needed.

## Fixed

- **OpenCode 2: a session was refused on every turn after the message that ended its newest summary was deleted** (error `MC-S06`). Magic Context removed the broken summary and scheduled a rebuild, but a second check on the host's own checkpoint ran first and refused the turn, on every later turn too. The session now continues from the newest summary that is still intact. The messages after it are sent in full until they are summarized again. If the first turn after the repair fails for another reason, such as a busy store, the next turn still recovers. On the turn after a recovery, one host instruction line that the summary covers (for example a date change) can leave the request. That costs one prompt-cache write, once, and Magic Context logs it.
- **OpenCode 2.3 and 2.4: a request could exceed the model's context window in a session that Magic Context had not summarized yet.** The last size check before sending did not count the session's tool definitions when the host recorded them under an agent name. In our test that hid about 5,000 tokens, and a 61,184-token request went to a 60,000-token window. The check now counts the tool list that the session's own last request carried, and prefers it over an older stored figure for the same model.
- **OpenCode 2.1 and later: a background run that hit the model's output limit lost its explanation.** These hosts retry such an answer twice and then report a plain failure, so Magic Context treated it as a generic error. It now records the run as cut off by the output limit, as it does on OpenCode 2.0. The token count of a run with several steps now includes every step and leaves out the host's automatic repeats.
- **OpenCode 1 and 2: the task that learns from user friction accepted an answer that was cut off by the output limit.** It then moved its position forward, so the messages behind the cut were never looked at. A cut-off answer now fails the run, and the next run reads the same messages again.
- **OpenCode 1: a maintenance run that reached its token budget could lose all of its results.** When the budget is reached, Magic Context refuses further tool calls and asks the model to wrap up. Tool calls that the model had issued just before were refused too, and the second refusal ended the run before the wrap-up request reached the model. Calls that were already running are now spared once, and the run ends only on a refusal after the wrap-up request.
- **Pi: the same loss of results in a maintenance run at its budget.** The fix is the same. It does not depend on the wording of the wrap-up request, because a Pi extension can change that text.
- **OpenCode 1: a turn that Magic Context refused showed only "Unexpected server error".** OpenCode 1 replaces a plugin's error text with a generic one. Magic Context now also shows its own explanation as a notice in the terminal that has the session open, for 15 seconds. OpenCode's web app and SDK callers still see the generic text.
- **Automatic search often timed out on the first turn after a pause** (issue 773). The search worker stopped five minutes after its last search, so the next turn started a new one and loaded its vectors within the one-second limit. The worker now stays for as long as the session's prompt cache lives after the last reply (at least five minutes, at most one hour), keeps its memory vectors loaded, and checks at most once a minute whether the store changed. A newly started worker now answers first and loads history vectors afterwards. In our measurement, the first search after a ten-minute pause took 23 ms, down from 134 ms, with identical results. The cost is memory: a kept worker holds about 25 to 200 MiB, and a process keeps at most four idle workers.
