# v0.49.32

This patch stops Pi's `ctx_search` from returning messages from a branch you left with `/tree`, and removes three more reads that blocked OpenCode's main thread while nothing had changed.

## Upgrading

- Restart OpenCode or Pi after updating. No database migration is needed.

## Fixed

- **Pi search returned messages from an abandoned branch (#807, thanks @LioTree):** after `/tree` moved to another branch and the session continued, `ctx_search` could return messages from the branch you left, once later summaries passed their message numbers. A branch change on Pi and Oh My Pi now rebuilds that session's message search index from the active branch, the same way OpenCode 2 already does after a revert. Until the rebuild finishes, message search returns no message results, and a search or automatic hint already in flight drops any message result from the old branch. Memories, notes, summaries and git results are unaffected.
- **Three OpenCode reads repeated when nothing had changed (#825, thanks @iceteaSA):**
  - **Dream backlog counts:** the sidebar recounted the dreamer's pending work on every poll, because any database write reset its cache. The sidebar and status display now reuse a count for up to 60 seconds. The dreamer's own scheduling still uses exact counts.
  - **Chunk coverage:** the check rebuilt each summary's search text from the index even when nothing in it had changed. It now reuses the previous result while the summary and its indexed messages are unchanged, and rebuilds as soon as either changes.
  - **Mis-scoped chunk scan:** every project registration, including each plugin reload, rescanned for misfiled search chunks. A finished scan is now remembered per project and embedding model, and runs again after a session's project changes.

  None of these changes what the model sees.
