# v0.49.49

This patch stops sessions near their context limit from rewriting the prompt for tiny summaries, and keeps Magic Context's per-project working files out of `git status`.

## Upgrading

Restart your host after updating. No database migration is needed.

## Fixed

- **No more tiny summaries near the limit (issue 886):** once a session reached the near-limit band, Magic Context summarized any history that had just left the recent tail, often one or two steps. Each of those summaries changed the cached prompt, so a session sitting in that band rewrote its whole prompt every few steps. A minimum size that should have prevented this never applied. Near the limit, a summary now waits until the history it covers holds at least 2% of the usable window, counting text and tool inputs (tool outputs leave the prompt by other means). Manual `/ctx-wrapup` and `/ctx-recomp`, usage at or above 95%, overflow recovery, and the recovery after switching to a model with a smaller window still summarize whatever is ready, so they never wait. Below the near-limit band nothing changes.
- **Working files no longer show in `git status` (issue 891):** Magic Context wrote its ignore rule into the shared `.cortexkit/.gitignore`, which itself showed up as an untracked file, so `git status` listed `.cortexkit/` after the first summary. Magic Context now writes `.cortexkit/magic-context/.gitignore` containing `*` whenever it creates that folder, for summarizer dumps and documentation proposals alike. It removes its own old entry from the shared file, leaves other tools' entries untouched, and deletes the shared file only if nothing else is left in it. `.cortexkit/magic-context.jsonc` stays trackable. `setup` no longer edits your repository's root `.gitignore`; lines it added before can stay.
