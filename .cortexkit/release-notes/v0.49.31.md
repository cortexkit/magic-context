# v0.49.31

This patch fixes four Oh My Pi and Pi problems from one detailed report, stops an OpenCode 2 `/goal` compaction from pushing every request past the context window, lets very large Pi sessions run without refusals, shortens how long Pi holds the database lock when queued drops land, and makes the dreamer's verify and memory-mapping tasks stop failing on valid answers.

## Upgrading

- Restart OpenCode or Pi after updating. No database migration is needed.

## Fixed

- **Every Oh My Pi turn refused after local midnight (#820, thanks @TheOrdinaryWow):** Oh My Pi adds a date and folder reminder row to the request after Magic Context has checked the turn's structure, and the check didn't expect it. From midnight on, every turn was refused until Oh My Pi restarted. The check now accepts that reminder only when it matches Oh My Pi's exact template, with a valid date and the session's own folder, in the position Oh My Pi uses. Any other extra row is still refused.
- **Oh My Pi Responses turns refused after a matching tag (#821, thanks @TheOrdinaryWow):** when the tag Magic Context re-applies equals the one the model echoed, the reply was prepared without its phase, so every later turn was refused. The phase is now kept in that case.
- **Pi's local embedding preflight never ran (#822, thanks @TheOrdinaryWow):** an early return skipped the pooling check, so session backfill retried every minute and never finished. The check now runs.
- **A Pi log line printed `[object Object]` (#823, thanks @TheOrdinaryWow):** the historian's fallback models now print by name.
- **OpenCode 2 `/goal` could push every request past the context window (#824, thanks @elmagow):** when OpenCode 2 compacts a long session, it adds a "recent context" block of raw conversation to its checkpoint, and in an agent session that block could reach millions of tokens. It was then sent on every request, and reverting didn't remove it. Magic Context already serves those messages itself, so on OpenCode 2.1 and newer its compaction answer now asks for no recent-context block. Sessions already affected, and OpenCode 2.0, have the block trimmed before the request is sent, and every request carrying a checkpoint is measured against the window first. No message that wasn't summarized yet is lost.
- **Very large Pi sessions were refused:** Pi sessions with around 200,000 or more tags could be refused, because a memory estimate counted far more than the session uses and tagging took too long. Sessions up to 250,000 tags now run, and the requests sent are unchanged.
- **Pi held the database lock for seconds when queued drops landed:** applying a large batch of queued drops rewrote a stored record once per drop while holding the shared database's write lock, up to about 10 seconds. It is now written once per batch, and the lock is held for a fraction of a second.
- **Pi's retrospective read reminder notices as if the user had written them:** it now strips them, as OpenCode already did.
- **Dreamer verify ignored `timeout_minutes`:** verify and verify-broad cut every batch at 4 minutes, whatever the configured task timeout, so slow models never finished a batch. They now keep starting batches until the configured deadline, and each batch can use the time left.
- **Dreamer memory mapping treated a valid empty answer as a failure:** when a model correctly left every memory in a batch unmapped, as the prompt allows, the answer was rejected and every fallback model was tried in turn. A well-formed empty answer now counts as a completed batch, and those memories retry later on their usual backoff. Malformed answers still fall back.
