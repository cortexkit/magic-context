# v0.49.80

This patch fixes six defects reported from a code review of 0.49.78, three in the OpenCode 2 adapter and three in background maintenance and memory search.

## Upgrading

Update the plugin with `npx @cortexkit/magic-context@latest doctor`, then restart your host. No database migration is needed.

## Fixed

- **OpenCode 2: a `/btw` side question after an interrupted turn could be sent unmanaged history** (issue 981). When a turn was refused before Magic Context had processed it, the unprocessed request replaced the one saved for side questions. A side question asked next could then go out with the raw session history. A request is now saved only after it has been processed, and a refused turn leaves the saved one as it was.
- **OpenCode 2: text removed by a revert could come back in a later request** (issue 979). After a revert, a new host checkpoint could reuse the number of a checkpoint from before the revert and be served that older checkpoint's summary, which still described the reverted text. A stored summary now belongs to one checkpoint only. A session that carries such a mixed record rebuilds its history once after the upgrade.
- **OpenCode 2: a failed model list request no longer stops every turn** (issue 980). When the host could not list its models, every turn on a model not seen before was interrupted with `usage-unavailable`, although the model's limits were known from the request. Magic Context now uses those limits until the model list works again. A request that is too large for the model is still refused.
- **Docs upkeep skipped commits made while a proposal was waiting** (issue 982). A `maintain-docs` run that found a proposal still pending recorded the newest commit as reviewed. Commits made in the meantime were never looked at, whether the proposal was then applied or dismissed. A waiting run no longer moves that marker.
- **Memory search could compare vectors from two embedding models** (issue 983). If the embedding model was changed while a search was running, memories embedded with the new model could be scored against a query embedded with the old one. Search now only uses vectors from the query's own model.
- **A memory edited during summarization could keep the embedding of its old text** (issue 984). When several new memories were embedded one after another and one was edited while it waited, it was embedded from its old text and never corrected, so search by meaning kept matching the old wording. The text is now read at the moment it is embedded. Embeddings stored this way before the fix are not rewritten.

Issues 982, 983 and 984 also affected Pi and Oh My Pi.
