# v0.50.0

This release checks every new memory against the ones you already have before saving it, adds `/ctx-rescore` to fix importance scores on older history, and lets `/ctx-wrapup 0` summarize a whole session. It also upgrades the shared database, so it can't be undone by installing an older version.

## Upgrading

- **Back up first.** The shared database moves from version 95 to 105 the first time an updated host starts. A 0.49.x plugin refuses the upgraded database, and the only way back is restoring a backup taken before the update. Copy `context.db` from `~/.local/share/cortexkit/magic-context/` in your home folder (the same place on Windows, macOS and Linux) while every host is closed.
- **Update and restart every host together.** OpenCode and Pi share one database, so once one host has upgraded it, a host still on 0.49.x refuses to run turns until it's updated too. Update the OpenCode plugin, the Pi plugin and the CLI to 0.50.0, then restart them.

## New

- **Memories are checked before they're saved.** After the historian summarizes a stretch of history, a second turn compares each new fact with your existing memories and decides whether it's new, already covered, a correction to an existing memory, or a duplicate to merge. This keeps the project memory from filling with near-duplicates and stale versions. It's on by default, with `historian.turn_two` (user config only) to switch it off. Headless Pi and Oh My Pi keep one pass, because the host process can exit before a second turn finishes.
- **`/ctx-rescore`** re-scores the importance of older history summaries. Summaries written before October's historian scoring fix can carry scores that make the wrong ones fade first. Run `/ctx-rescore` (or `/ctx-rescore --project`) to preview what would be re-scored and how many model calls it takes, then `/ctx-rescore confirm <snapshot-id>` to start. `status`, `pause`, `resume`, `cancel` and `undo` control a running job. New scores apply at the next natural history rebuild, so rescoring never forces a cache rewrite.
- **`/ctx-wrapup 0`** summarizes the whole session, keeping no recent messages raw.
- **Memory history in the dashboard.** The memory browser shows a timeline of changes to each memory and to the project, by the dreamer, the historian, the agent and you, with a preview-and-confirm undo. Session history rows show their importance scores, including scores waiting for the next rebuild.
- **`MAGIC_CONTEXT_CONFIG_PATH`** points Magic Context at one exact user config file. It must be an absolute path. If the file is missing, Magic Context warns instead of falling back to the default location. Project config still applies on top.
- **`doctor history heal`** plans and applies repairs to OpenCode 1 session history (the plan is read-only; applying needs every host closed and backs up first).

## Changed

- **Memory edits are revision-checked.** A `ctx_memory` update or archive applies only to the version of the memory the agent saw. If the memory changed in the meantime, the agent is told it's unchanged instead of overwriting the newer version.
- **`ctx_search` looks up memory ids among active memories only,** not archived ones.

## Removed

- **The experimental Rust transform mode.** `transform_mode: "rust"` and `rust_pipeline` are ignored; every host uses the built-in transform.

## Fixed

Everything fixed in 0.49.36 to 0.49.39 is included.
