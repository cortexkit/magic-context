# v0.49.38

This patch makes hosted reranking work with Voyage, and lets Pi's dreamer fall back to the configured provider when a translated one has no credentials.

## Upgrading

- Restart OpenCode or Pi after updating. No database migration is needed.

## Fixed

- **Hosted reranking failed with Voyage:** with `rerank.provider: "remote"` pointed at Voyage, every `ctx_search` reported `Reranking skipped: http_400` and kept its original order. Magic Context sent a `top_n` field, which Voyage's rerank API refuses, and it read scores only from a `results` list, while Voyage answers under `data`. Requests now leave `top_n` out, since Cohere, Jina and OpenRouter score every document without it too, and replies are read from either list. Thanks to @null-axiom for the precise report (#872).
- **Pi dreamer tasks failed instead of falling back when a translated provider had no credentials:** with a dreamer model such as `openai/<model>`, Pi first tries the subscription form (`openai-codex/<model>`) and falls back to the configured provider if that form has no credentials. The dreamer runs Pi in a mode that reports the missing key as a failed prompt, not as a process exit, so the fallback never ran and each task failed with "No API key found for openai-codex". Both reports now trigger the fallback. Thanks to @XWIlluDelu for the precise report (#873).
