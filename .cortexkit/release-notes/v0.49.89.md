# v0.49.89

This patch changes what a `/ctx-recomp` that stops partway does, and it protects a data folder that is a symbolic link.

## Upgrading

Update the plugin with `npx @cortexkit/magic-context@latest doctor`, then restart your host. No database migration is needed.

## Changed

- **A `/ctx-recomp` that stops partway now keeps your current history.** Before, a full rebuild that failed partway replaced the old summaries with the part it had finished. The messages behind that part lost their summaries. On OpenCode 2, after a manual `/compact`, those messages could be missing from later requests until the rebuild was run to the end (28 messages in our test). Now a stopped rebuild publishes nothing unless it already covers everything the current summaries cover. The result is headed "Paused", says how far the rebuild got, and says that your history is unchanged. The next `/ctx-recomp` continues from that point and does not send the finished part to the model again. This holds on OpenCode 1, OpenCode 2 and Pi.
- **A rebuild that cannot get past one point is discarded, not repeated forever.** If a resumed rebuild stops again at the same message, with the same input and no model failure in between, Magic Context discards the unfinished part and says so. Your current history stays as it is. A model or provider failure never causes a discard; such a rebuild stays paused.
- **`/ctx-recomp` with a range refuses while a full rebuild is paused.** It tells you to run `/ctx-recomp` without arguments first. A full rebuild started while a range rebuild is unfinished discards the range leftovers and starts from the first message.
- **A data folder that is a symbolic link is now made owner-only at its target.** Earlier releases opened a linked data folder, but the check that makes the store private skipped it without a message. Magic Context now follows the link and makes the target folder private (`0700` for directories, `0600` for files), unless you turned owner-only storage off. It does this only when the target is not a filesystem root, your home folder or a mount point, and holds nothing but Magic Context's own files. If the target holds anything else, Magic Context leaves its permissions alone and logs how many foreign entries it found. Give the store a folder of its own so it can be protected. Links inside the data folder are not followed, and a broken link does not stop the host from starting. The configuration reference describes the rule under "Owner-only storage".

## Fixed

- **A rebuild that reached the end of what can be summarized was reported as partial.** When only messages with nothing to summarize remained, `/ctx-recomp` reported a partial result and asked you to run it again. It now completes, keeps the later summaries as they are, and says which messages stay as they are.
- **`/ctx-recomp` on a session whose messages are all still in the recent raw part said it had lost a lock.** It now says there is nothing to rebuild yet.
