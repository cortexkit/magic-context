# v0.49.58

This patch makes the dreamer work on OpenCode 2.3's Claude Agent provider, lets a manual `/ctx-dream` use dreamer settings changed while the host runs, keeps tags and `ctx_reduce` reminders out of Pi and Oh My Pi sessions that cannot call `ctx_reduce`, moves the historian's debug files out of your project, and stops Oh My Pi WebSocket continuations from being refused over a field the provider never receives.

## Upgrading

Update the plugin and restart the host. OpenCode 2 does not update npm plugins by itself, so update it as the docs describe. No database migration is needed.

## Fixed

- **OpenCode 2.3, Claude Agent provider: dreamer tasks invented their own output format and committed nothing (issue 935, thanks @mgt-l for the report and the kept child sessions):** OpenCode 2.3's `claude-agent` provider builds the system prompt from Claude Code's own prompt and drops the request's first system part. Magic Context's hidden runs put each task's instructions, including its output format, in exactly that part, so the model never saw them. On that provider the task's instructions now go at the start of the run's first message, identical on every step of the run so the provider's prompt cache holds. This covers the dreamer tasks and the historian. Requests to every other provider are unchanged, byte for byte.
- **OpenCode 2: a manual `/ctx-dream` ignored dreamer settings changed after startup (issue 936, thanks @mgt-l):** the configuration reference marks the dreamer's model, variant and fallback models as live, and scheduled runs already followed changes. A manual `/ctx-dream` used the settings the plugin started with. It now reads the live configuration too. On OpenCode 1, a manual `/ctx-dream` also honours a dreamer turned off after startup.
- **Pi and Oh My Pi: sessions that cannot call `ctx_reduce` got tags and reduce reminders (issue 904, thanks @TheOrdinaryWow):** Magic Context added `§N§` tags, `ctx_reduce` guidance and both reduce reminders to sessions whose tool list has no `ctx_reduce`, such as an Oh My Pi task child spawned from plan mode. Now all three appear only while the session's next request can call the tool, checked on every request. When another extension removes the tool or puts it back, the session rebuilds its prompt once, at that request, and tags that come back keep their numbers. Oh My Pi task children are now treated as subagents, as on OpenCode: no history summaries and no note reminders. A forked session that inherited history from its source keeps it.
- **Historian debug files were written into your project (issue 934, thanks @zapadinsky):** when a historian pass fails its checks, Magic Context keeps the model's response for debugging. These files went to `.cortexkit/magic-context/historian/` inside the project. They now go to the operating system's temporary directory, per session, next to Magic Context's log: `<temp dir>/<host>/magic-context/historian/<session id>/`. Nothing is written into the project for them any more. `doctor` and issue bundles look in the new place and the old one. Existing files in your projects are left alone; the folder is git-ignored and safe to delete.
- **Oh My Pi: WebSocket continuations refused over a completion time (issue 921, thanks @RiAnBee for the report and the fix in #933):** Magic Context checks that each chained continuation extends the request before it. That check compared an older message's completion time and context snapshot, which the provider never receives, so a change there refused the continuation. Those fields no longer count. Message text, roles, the provider's own response items and tool arguments are checked as before.
