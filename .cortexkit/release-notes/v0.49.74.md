# v0.49.74

This patch fixes two cases where Magic Context could act on stale text: an OpenCode 2 side question after you edit an earlier message, and nightly memory verification after a memory is corrected mid-run.

## Upgrading

Update the plugin and restart OpenCode, Pi or Oh My Pi. No database migration is needed.

## Fixed

- **OpenCode 2 side questions could resend a message you had edited (#971, thanks @iceteaSA):** a side question reuses the prompt Magic Context last prepared, so it stays on the cached prefix. After you edited or reverted an earlier message, a side question asked before your next normal turn could still carry the old text. Magic Context now drops the saved prompt when a message is edited or reverted. It also checks that the history before the newest message is unchanged before reusing the saved prompt; the check hashes image bytes directly, so long sessions with many images stay fast. When nothing was edited, side questions send exactly the same bytes as before.
- **Nightly memory verification could undo a correction made while it ran (#972, thanks @iceteaSA):** verification shows the model a batch of memories, which can take minutes. If an agent corrected one of those memories in the meantime, an "update" or "archive" answer was still applied to it, replacing the correction or archiving it. Every answer is now applied only if the memory still has the text the model checked; otherwise it's skipped and checked again on a later run.
