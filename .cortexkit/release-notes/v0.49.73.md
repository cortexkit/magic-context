# v0.49.73

This patch makes `/ctx-wrapup` shrink the prompt on your next message, and stops it from planning with the wrong context window after a restart.

## Upgrading

Update the plugin and restart OpenCode, Pi or Oh My Pi. No database migration is needed.

## Fixed

- **`/ctx-wrapup` didn't shrink the prompt until the next rebuild (#967, thanks @JohanTG):** below the execute threshold, a finished wrapup saved its new summaries, but the next request still carried every raw message they covered. The summaries only reached the model at the next natural rebuild, which could be many turns later. A successful wrapup now applies its new history on the very next message, as `/ctx-flush` does: the summaries come in and the covered raw messages leave the request. The cached baseline isn't rebuilt. A wrapup that adds no summaries changes nothing. If the host restarts before your next message, the summaries apply at the next rebuild instead, and the completion message says so.
- **`/ctx-wrapup` planned with a 128,000-token window after a restart (#967):** when no model had been used yet in the running host, the command sized its chunks for a 128,000-token window, which made a wrapup on a large-window session take far longer than needed. It now uses the session's selected or last model and that model's real window, and refuses with a clear message when no window is known.
