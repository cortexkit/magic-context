# v0.49.46

This patch fixes two OpenCode 2 problems that kept sessions large and expensive: tool catalogs piling up when MCP servers connect and disconnect, and oversized requests after switching to a model with a smaller context window. OpenCode 2 checkpoints also show a short note instead of the full history.

## Upgrading

- Restart OpenCode or Pi after updating. No database migration is needed.
- On OpenCode 2, avoid going back to 0.49.45 or earlier after this version has written a checkpoint. Older versions read the new checkpoint note as the summary of earlier history in subagent sessions.

## Fixed

- **OpenCode 2 no longer piles up tool catalogs from MCP servers:** each time an MCP server connected or disconnected, OpenCode 2 added a new copy of the tool catalog to the conversation, and Magic Context removed old copies only when a newer one restated every server at once. MCP changes arrive one server at a time, so old copies were almost never removed, and a long session could carry hundreds of them. Magic Context now removes a copy once every server it mentions has a newer entry, including copies already covered by the history summary. Removal happens only on a turn that already rebuilds the prompt. In a test run that toggled an MCP server every few turns, the request went from 39 catalog copies to 1, and prompt rewrites from 30 to 6. Thanks to @dhaern for the detailed report (#886).
- **Context usage is measured against the right window when the provider reports no usage:** in that case Magic Context counts the request itself. It divided by the wrong window size, which made usage look 20–30% lower than it was, and its 95% safety lines ignored a model's input limit. Both now use the window the provider's own readings use, capped by the input limit (#886).
- **Switching to a model with a smaller context window no longer sends oversized requests:** after switching, for example, from a 1M-token model to a 200k one, Magic Context summarized one chunk of history per turn and sent each request anyway, so the provider rejected turn after turn. It now keeps summarizing within the same turn until the request fits. If it still can't fit, it refuses the turn with a clear message instead of sending a request that would fail. The next turn continues. In a real OpenCode 2 run, the switch took one turn instead of nine failed ones. Thanks to @dragon-Elec for the report (#889).
- **OpenCode 2 checkpoints show a short note:** when Magic Context adds a checkpoint to keep an OpenCode 2 session fast, the conversation showed the whole history summary, memories included, under a "Compaction" divider. It now shows a one-line note saying the history is unchanged. The model still receives the same history as before (#889).
- **`doctor --issue` keeps the wording of log lines:** issue reports replaced the text of almost every log line with `<text omitted>`, which left them hard to read. The fixed wording of Magic Context's own log lines is now kept, and only the values inserted into them are judged one by one: numbers, durations and model names are kept, paths and ids are replaced with aliases, and anything else is left out.
- **`ctx_memory` argument descriptions name the placeholders:** some hosts require every argument. The descriptions now say to pass an empty list for `ids` when writing, and empty text for `content` when archiving or reading.
