# v0.49.63

This patch fixes OpenCode 2 sessions that run with Magic Context's compaction off: OpenCode's own automatic compaction no longer repeats on every step. It also stops the record of a `/ctx-flush` decision from being lost now and then.

## Upgrading

Update the plugin and restart OpenCode or Pi. No database migration is needed.

## Fixed

- **OpenCode 2: native compaction repeated on every step with Magic Context's compaction off (issue 944, thanks @endynamoo for the report and the diagnosis in pull request 945):** with `compaction.enabled: false`, Magic Context leaves context management to the host. But on OpenCode 2 it still put back the history that sat before OpenCode's own compaction checkpoint. The request never shrank, so OpenCode compacted again on the next step, and again after that. With compaction off, Magic Context now sends OpenCode's checkpoint and the messages after it exactly as OpenCode built them. When one of its passes fails in that mode, it sends OpenCode's own request instead of refusing the turn, because the refusal only protected the restore. With compaction on, nothing changes.
- **The record of a `/ctx-flush` decision was sometimes lost:** each pass's decision is written to Magic Context's store a moment after the pass. On Pi and Oh My Pi that write was dropped whenever the next run ended first. On OpenCode it gave up at once when another connection, such as the host's own message indexing, held the store's lock. The write now survives a finished run, and on OpenCode it retries for about two seconds without blocking the host. The flush itself always happened and requests are unchanged; only the record, which diagnostics and the cache analyzer read, was missing.
