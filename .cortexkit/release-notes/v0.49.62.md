# v0.49.62

This patch stops Pi from rewriting earlier replies on every tool turn when the model's provider adds an empty text block after a tool call. The rewrites cost most of the prompt cache on each turn.

## Upgrading

Update the plugin and restart Pi. No database migration is needed.

## Fixed

- **Pi: prompt cache lost on almost every tool turn with Gemini (issue 948, thanks @enterlet for the report and the root-cause analysis):** some providers, Gemini through `pi-antigravity` among them, end a reply that calls a tool with an empty text block. Magic Context gives no tag to an empty block, but its check for edited replies still counted the block, so it judged the reply edited on the next turn. It then gave the reply a new tag number and rewrote it in the request. That changed bytes the provider had already cached, so most of the conversation was sent uncached again, and cache hits fell from about 90% to 15–30%. The check now skips exactly the blocks that get no tag, so the request only grows at the end. A reply whose text really changed still gets a new number, as before. Replies already renumbered keep their current number. Oh My Pi drops the empty block itself, and OpenCode has no such check, so neither was affected.
