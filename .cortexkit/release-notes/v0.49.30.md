# v0.49.30

This patch fixes a Pi session stalling on replies its model wrote as blank drop markers, cuts main-thread CPU on long OpenCode 2 sessions, repairs `doctor repair-db`, and adds logging for hidden historian sessions on OpenCode 2.

## Upgrading

- Restart OpenCode or Pi after updating. No database migration is needed.

## Fixed

- **Replies written as `[dropped ]` stalled a session (#815, thanks @tevenfeng):** Magic Context removes assistant replies that contain nothing but drop markers, so the model doesn't copy them and stop. It recognized `[dropped]` and `[dropped N]`, but not the blank form `[dropped ]` some models write. Those replies stayed in history and the model kept stopping. All three forms are now removed, with one rule shared by OpenCode and Pi. The removal still happens only on a pass that rebuilds the prompt anyway, so it costs no extra cache write.
- **Main-thread CPU on long OpenCode 2 sessions (#817, thanks @iceteaSA):**
  - **The sidebar usage query:** it read every message of the session on each sidebar poll. It now uses the session index. On the reporter's long sessions, one poll took about 19 ms before and well under a millisecond after.
  - **Message times:** every pass re-read the creation and completion times of every message, although a finished message's times never change. Times are now reused for user messages and finished replies, and re-read only when OpenCode changes or rewrites a message. The times shown to the model are byte-identical.
  - **The history boundary check:** a per-pass check read full summary rows when it needs only two fields. It now reads just those fields.
- **`doctor repair-db` could not salvage a damaged database:** its recovery replay failed on every SQLite version, because the shell's defensive mode blocks the schema writes that recovery needs. Recovery now turns defensive mode off on the fresh replay database only. Every row comes back, along with statistics and search-index definitions. The backup before repair and the integrity checks are unchanged.

## Diagnostics

- **Hidden historian sessions on OpenCode 2 (#818, thanks @Ven0maus):** Magic Context now logs when it creates each hidden historian or dreamer session, and whether it keeps or removes it afterwards. The log also records the `keep_subagents` value in effect at startup. These lines help find why some users see a "session not found" message on OpenCode 2.2.
