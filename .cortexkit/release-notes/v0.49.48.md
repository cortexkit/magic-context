# v0.49.48

This patch stops OpenCode sessions from replaying an outdated todo list when the agent uses a custom todo status.

## Upgrading

Restart OpenCode after updating. No database migration is needed.

## Fixed

- **Todo lists with custom statuses are kept (issue 892):** OpenCode's `todowrite` accepts any status or priority text, such as `blocked`, but Magic Context only recognised the four built-in statuses and three priorities. It ignored any other list, so it kept the older list and showed it to the agent as its latest plan whenever the prompt was rebuilt. Magic Context now keeps every list the way OpenCode stores it, and treats every status other than `completed` and `cancelled` as still open. A list it can't read at all clears its saved copy instead of leaving an old one in place. Lists that only use the built-in values are stored exactly as before. Pi is unchanged, because its `todowrite` tool already refuses other values.
