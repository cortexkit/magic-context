# v0.49.83

This patch fixes three nightly maintenance faults: a retrospective that could read the same messages again every night, a daily run that did nothing for small projects, and file mapping that retried the same memory every day.

## Upgrading

Update the plugin with `npx @cortexkit/magic-context@latest doctor`, then restart your host. No database migration is needed.

## Fixed

- **The retrospective could re-read the same window every night** (issue 990, thanks @null-axiom). The retrospective reads your recent messages for friction and writes lessons as memories, then stores how far it has read. When a run hit one of its limits (80 new messages per session, 240 per run, the prompt budget, or more sessions than one run reads), it moved the stored position back to just before the first message it had not finished, but it still sent later messages to the model. The next run then received the same messages again and could write the same lessons again. Now a run that sends messages stores a position at or after the newest message it sent, and messages that share one timestamp are sent together or not at all. A position that is already stuck moves on the first run after the update. A group of messages with one timestamp that can never fit in a run is skipped, with a log line that says how many.
- **Importance scoring ran every day for projects with fewer than 10 memories and did nothing** (issue 989, thanks @null-axiom). The task needs at least 10 memories to work, but its schedule check and its backlog count did not apply that minimum. Such a project showed a backlog that never cleared and had one empty run per day. The check and the count now use the same minimum as the task.
- **File mapping tried a memory it could not link to any file again every day** (issue 989, thanks @null-axiom). File mapping links a memory to the files that back it, so the nightly check knows when to look at it again. A memory that matches no file was tried again after at most 24 hours, without end, one model call each time. Now the wait keeps doubling up to 7 days, and a change to the memory's text or category makes it eligible at once. Only a real "no file found" answer counts as a failed try: a provider error, a timeout or a run that could not start no longer lengthens the wait, and one run counts a memory once. A memory that is waiting no longer counts as backlog and no longer starts a run.

## Changed

- Every completed retrospective run now logs the position it started from, the newest message it read, the position it stored and the position it read back. If a retrospective ever seems stuck again, that line shows which step lost the advance.
