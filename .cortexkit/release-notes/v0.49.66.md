# v0.49.66

This patch fixes history that could go missing from a request on OpenCode, and makes long Pi sessions faster. The fixes come from a code audit.

## Upgrading

Update the plugin and restart OpenCode or Pi. No database migration is needed.

## Fixed

- **History could be left out of a request on OpenCode (1 and 2):** when another connection refreshed the session's history summary while a request was being prepared, the request could pair the older summary with the newer cut-off point. The messages between the two cut-off points then appeared neither as summary nor as raw messages. A request now always uses the cut-off point that belongs to the summary it sends. The same holds when a summary ends partway through a message, on OpenCode and on Pi.
- **A very large new message could go out unchecked on OpenCode:** on a session that was running normally, one very large new message (for example a pasted log) was sent without checking that the request still fit the model's window. Such a request now goes through the same fit check as other oversized requests. Requests that fit are unchanged.
- **OpenCode 2 refused some requests that fit:** in sessions with a host conversation checkpoint, a cautious size estimate for a provider Magic Context had not measured yet could refuse a request that fits. The refusal now needs a measured count, or a request that is clearly over the window even without the extra caution.

## Faster

- **Long Pi sessions:** each new message no longer walks the whole session branch again to number messages.
- **Every OpenCode request:** a request that resends the cached history no longer counts tokens it does not use, and saving new history summaries reads only the new rows while it holds the database lock.
