# v0.49.24

This patch fixes several ways Oh My Pi could refuse every turn, keeps memory and note tool calls working on providers that drop optional arguments, and fixes two cases where the summarizer stopped summarizing.

## Upgrading

- Restart OpenCode, Pi or Oh My Pi after updating. No database migration is needed.
- The `ctx_memory` and `ctx_note` tool definitions change in this release, so each open session rebuilds its prompt cache once, on its next turn.

## Fixed

- **Oh My Pi:** each of these left a session refusing every turn until a new session was started.
  - Resumed sessions were refused when Oh My Pi added a tool-control message to the request. Thanks to @tsankotsanev, who also sent the fix in #786.
  - Dropping a tool call could leave two assistant messages next to each other, and Oh My Pi's `Continue.` repair message wasn't expected. Thanks to @TheOrdinaryWow.
  - The first turn after a restart was refused when another session's background preparation was cancelled, including when several subagents started at once. Thanks to @Zireael.
  - A chained continuation was refused after a summary was folded into the history, because the history block's timestamps changed. Thanks to @Zireael.
  - A message typed while the agent was working was refused, because Oh My Pi's steering wrapper wasn't expected. Thanks to @Zireael.
  - After an aborted turn, every Claude turn was refused, because Oh My Pi drops an empty aborted reply that Magic Context still expected. Thanks to @TheOrdinaryWow.
- **`ctx_memory` and `ctx_note` on providers that drop optional arguments:** some providers, such as InferenceNet on OpenRouter, send only the first argument when a tool marks nothing as required, so almost every call failed. The key arguments are now required. Values that don't apply to an action can be sent empty, and when updating or merging a memory the model passes its current category to keep it. Thanks to @garionberg.
- **Summarizer:**
  - A session that runs from a single prompt is summarized again once it passes the execute threshold, instead of waiting for the 85% force band. Thanks to @yelrom-liively.
  - After an OpenCode session leaves Rust transform mode, the summarizer no longer refuses forever on gaps left by notification-only messages. Thanks to @iceteaSA.
- **Task permissions:** a task permission that denies everything and then allows named agents no longer hides the Task tool. Thanks to @selfagency for the report and @DreamchaserLG for the fix in #787.

## Changed

- When you answer a question that an Alfonso agent asked you, the summarizer now records your answer as your own words instead of dropping it with other system notices.
