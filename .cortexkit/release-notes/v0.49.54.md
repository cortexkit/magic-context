# v0.49.54

This patch makes long Pi and Oh My Pi sessions without summaries much faster to prepare each turn, and makes the emergency drop work as intended near the end of the window.

## Upgrading

Restart your host after updating. No database migration is needed.

## Fixed

- **Pi and Oh My Pi: slow turn preparation on long sessions (issue 910, thanks @zhexulong):** on a long session without summaries, a cache of per-part token counts was smaller than the session, so every turn evicted it in the order it read it and every lookup missed. The request-size check also counted every message's tokens again on every turn. The cache is now keyed by a digest of each part's content, and the size check reuses the counts the turn already took. At 50,000 messages an appended turn went from 9.0 to 4.2 seconds, and token counts per turn from about 113,000 to 14. The requests sent to the model are unchanged.
- **The emergency drop sometimes skipped when the window was nearly full (issue 905, thanks @dhaern):** the emergency drop works out how much of the request it can't remove and drops tool results until the rest fits. It counted everything that the same pass's queued drops had already removed as content it couldn't remove, so after a large queued drop it could decide there was nothing to do. It now counts only what the request it sends still holds, on OpenCode and on Pi.
- **Pi and Oh My Pi: a background helper that failed to start ran without its tools:** Magic Context's background helpers (the summarizer, and the dreamer that maintains memories) load their tools when they start. On Oh My Pi, a startup failure (for example, storage that can't be opened) was hidden: the helper still called the model without its tools and reported success. A helper now stops before any model call when its startup fails, and the task reports the startup error, on Pi and on every supported Oh My Pi version.
- **OpenCode 2: thinking that carries only a signature was left out of size estimates (issue 905):** OpenCode 2 stores the signature of a thinking block with no visible text in a different place than OpenCode 1. Magic Context didn't find it there, so such a block counted as nothing toward the request's size. It now counts the same as on OpenCode 1.
