# v0.49.28

This patch fixes two dreamer problems: memory mapping falling behind in large projects, and Pi dreamer tasks stopping at 30 minutes regardless of their configured timeout.

## Upgrading

- Restart OpenCode or Pi after updating. No database migration is needed.

## Fixed

- **Memory mapping falling behind (#809, thanks @iceteaSA):** the dreamer maps memories to source files in batches of five, each given a fixed four-minute slice. In projects where a batch regularly needs close to four minutes, two timed-out batches in a row stopped the night's run, so only a few memories were mapped each night and the backlog kept growing.
  - **What happens now:** a timed-out batch is split into smaller batches (five becomes two, two and one), and those run straight away in the same run. Mappings a timed-out batch already saved are kept, and only the rest are retried.
  - **When a run still stops:** only after a single memory times out twice in a row with nothing saved.
  - **Settings:** none added. The per-batch slice and the task timeout are unchanged.
  - **Hosts:** OpenCode and Pi.
- **Pi dreamer tasks stopping at 30 minutes (#784, PR #808, thanks @izhangzhihao and @mvanhorn):** on Pi and Oh My Pi, each dreamer task runs in a child process that was always stopped after 30 minutes, so a task configured with a longer `timeout_minutes` was cut off early. The child process now gets the task's own timeout plus five minutes, so the dreamer's timeout always decides and reports the right reason. The user-memory review task now uses its own configured timeout too.
