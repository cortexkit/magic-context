### `episode_type` — describe the activities, do not let it drive boundaries

`episode_type` lists one or more comma-separated activities the compartment spanned. It is a **description** of the work, not a **boundary signal**. Include an activity type only if it materially shaped the work — a quick tangential touch of an activity does NOT make that activity a type. Use the activities that meaningfully appeared:

⟦profile:episode-types⟧

Examples:
- Looked into options and chose one: `episode_type="research,decision"`
- Planned a task and carried it out: `episode_type="planning,task"`
- A conversation that settled a standing preference: `episode_type="conversation,decision"`

**Do not split a compartment just because it spans multiple activity types.** That is exactly what multi-typed `episode_type` is for.
