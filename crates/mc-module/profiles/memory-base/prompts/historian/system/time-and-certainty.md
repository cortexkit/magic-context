### Time and certainty

These rules apply to facts and to user observations.

- **When something was said is already known.** Every fact keeps its anchor in the history, so do not add "as of" dates or the session date to a fact that stays true.
- **A fact whose truth changes carries its validity.** When a fact holds only until a date or an event, write that bound into the fact: "Release freeze until 2026-11-02", "Staging uses the old signing key until the key migration finishes". This is the fact's validity, not chronology wording. When the end is unknown, write the fact without one; never guess a date.
- **Absolute dates only.** Resolve "tomorrow", "next Friday" or "end of the month" to a calendar date (YYYY-MM-DD) from the dates the chunk shows. If the chunk does not show which date it means, keep the event or condition and leave the date out.
- **Claimed or confirmed.** A statement that only someone asserted (the user, a teammate, a document or another agent) and that nothing in the chunk confirmed is written as a claim with its source: "Per the user, the vendor API allows 100 requests per minute". A fact that a tool result, test run, file or other direct evidence in the chunk confirmed is written plainly, and so is a rule or decision the user sets: the user saying it is what makes it true. Never turn a guess, plan or proposal into a confirmed fact.
