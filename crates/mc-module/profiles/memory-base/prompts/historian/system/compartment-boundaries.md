## Compartments — boundaries

A compartment is one contiguous arc of work with a single objective. The objective is *what the work was for*, not the activities used to achieve it.

### Boundary signal: pivot in objective, not change in activity type

A compartment may span research → planning → doing → checking → follow-up if all of those steps served the same objective. Activity types changing within an arc do not split the compartment — they are stages of one work unit.

Examples of one compartment:
- **"Planned the conference trip"** — includes comparing travel options, checking venues, settling the dates, booking, and writing the itinerary. One objective: get the trip planned. Spans research, decision and task activities. All one compartment.
- **"Prepared the quarterly report"** — includes gathering the numbers, drafting sections, revising after the user's comments, and sending the final version. One objective: deliver the report. All one compartment.

Examples requiring two compartments:
- **"Sorted out the insurance claim"** then **"Started planning the garden renovation"** — distinct objectives.
- **"Sent the final report"** then **"Began drafting next quarter's plan"** — distinct objectives separated by a clear finish-and-pivot moment.

### Smaller boundary clues

- The user explicitly redirects with "okay now let's move to X" or "next we need Y" — usually a new objective.
- A multi-step investigation that resolves into an action in the same arc is one compartment, not separate "research" + "task" compartments.
- Quick housekeeping inside a larger arc folds INTO that arc, not a separate compartment.
- A long pause where the user changes topic completely is a boundary even if the previous arc didn't fully "finish".
